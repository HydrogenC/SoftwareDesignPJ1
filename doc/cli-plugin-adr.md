# CLI 插件框架 ADR

## 1. 属性处理、冲突和撤销

`handles` 和 `apply` 接收只读的 `ShapeView`，可以检查类型和子部件 ID。宿主按注册顺序检查 `handles`。没有匹配项时使用图形的属性白名单，有多个匹配项时报出处理器名称并拒绝修改。

处理器通过 `AttributeWriter.set` 修改目标及其后代。写入器记录节点 ID、属性和修改前后的值，处理结束后关闭。`set` 成功后才进入历史，失败则按逆序恢复已完成的修改。撤销逆序恢复，重做按原顺序重放。两者按 ID 查找图形，因为重做创建可能产生新实例。图形的属性方法须能恢复原值，拒绝输入时须保留当前值。

## 2. 特殊图形读回与结构不变量

`ShapeFactory.forSvg` 先按 `data-kind` 查找 provider，并检查它支持当前 SVG 标签。找不到时按标签名查找。`SvgReader` 先收集显式 ID 并拒绝重复，再按源码顺序为缺少 ID 的节点分配可用 ID。provider 接收已构造的直接子节点用于检查，返回尚未挂入父容器、也未挂子节点的图形。读入器和工厂负责挂载与索引，全部成功后才替换当前文档。

换父和删除前，先用 `assertCanRemove` 检查原父容器的约束。解组调用 `assertCanUngroup`，批量分组和解组均在修改前检查涉及的节点。同父换序不改变归属。新增子树在挂载前检查子树内部以及与现有文档的 ID 冲突。

`BoxProvider` 用 `ShapeCreationContext.create` 创建 `<id>-rect` 和 `<id>-label`，由 `Document.add` 检查整棵新增子树。`Box` 保存为 `<g data-kind="box">`。启用插件时，两个派生 ID 必须对应类型正确的直接子节点，部件缺失、类型错误或嵌套位置错误都会使读入失败，原文档和历史继续有效。禁用插件时由普通 `g` provider 读入，保留可识别的 SVG 子节点。

`Box` 允许额外子节点和嵌套。两个必要部件可在同一父容器内换序，不能单独删除或换父。部件按派生 ID 查找，换序不影响设置属性和读入。整个 `box` 仍可移动、分组或删除。`BoxAttributes` 分别设置矩形的 `fill` 和文本的 `text`。如果读入的矩形原本继承父组颜色，撤销时移除新设的 `fill`，恢复继承。

## 3. 注册事务和清单校验

代码和配置装配都调用 `PluginHost.load`。代码入口导入插件实例和清单。配置加载器先验证整份配置，再按数组顺序解析路径、读清单和取默认导出。`enabled: false` 的条目跳过导入。

宿主先验证清单结构，再暂存 `activate(ctx, options)` 中的注册。激活结束后按类别比较声明和实际名称，清单中的顺序不参与比较。帮助和标签使用实际注册顺序。重复注册、激活异常或清单不符时，宿主丢弃该插件的暂存注册。

配置加载器分别处理入口解析和模块执行。入口找不到时报模块不存在，缺少传递依赖或执行模块出错时报激活失败。后续条目继续加载。

## 4. 未保存标记与祖先传播

`modified-star` 按 ID 将当前节点与上一次成功 `save` 或 `read` 后的快照比较，检查类型、SVG 标签、属性键值、文本和有序子节点。属性顺序不参与比较。撤销到基准时星号消失。读写失败时沿用原基准，`init` 清空基准，所以新画布立即标星。新建节点如果没有对应的基准内容，也立即标星。

子节点变化时，其祖先容器直到画布根都会标星。新增、删除、换父和换序会改变父容器的子节点列表。例如，将一棵内容未变的子树换到另一容器时，被移动节点的标记保持原状，两个父容器及其祖先标星。删除节点后，变化由仍可见的祖先显示。

基准快照和比较缓存存放在插件实例中。同次渲染共享不可变的 `ShapeView`，祖先行和子行可复用比较结果。`tree <id>` 使用同一份基准。

标签按注册顺序用一个空格追加到行尾。默认先加 `(box)`，再加 `*`，如 `g#n1 (box) *`。两个装饰器独立读取 `ShapeView`。
